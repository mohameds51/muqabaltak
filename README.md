# مقابلتك — V3 (اختبار الطلب)

صفحة منتج + صفحة تسجيل اهتمام + حفظ التسجيلات في Postgres + Meta Pixel (جاهز للتفعيل).
**لا يوجد أي دفع.** لا Stripe ولا Paddle ولا حدث `Purchase`.

---

## هيكل المشروع

| الملف | الوظيفة |
|---|---|
| `index.html` / `styles.css` / `script.js` | صفحة المنتج |
| `checkout.html` / `checkout.js` / `pages.css` | صفحة تسجيل الاهتمام |
| `privacy.html` `terms.html` `refund.html` `contact.html` | الصفحات القانونية والتواصل (**مسودات**) |
| `config.js` | **الإعدادات المركزية**: Pixel ID، بيانات التواصل، اسم صاحب المشروع |
| `common.js` | موافقة ملفات الارتباط، تحميل Pixel، حفظ UTM/fbclid |
| `api/register.js` | Vercel Function لحفظ التسجيل (تحقق، منع تكرار، مكافحة سبام) |
| `db/schema.sql` | جدول قاعدة البيانات |
| `.env.example` | أسماء متغيرات البيئة (بدون أسرار) |
| `package.json` | يعرّف مكتبة `pg` التي يثبتها Vercel تلقائيًا |

---

## 1) النشر على Vercel

1. ارفع محتوى المجلد إلى مستودع GitHub (ملف `.gitignore` موجود).
2. في Vercel: **Add New → Project** واختر المستودع.
   - Framework Preset: **Other**
   - Build Command: اتركه فارغًا
   - Output Directory: اتركه فارغًا (الجذر)
3. اضغط Deploy. سيكتشف Vercel مجلد `api/` ويحوّل `api/register.js` إلى Function تلقائيًا، ويثبت `pg` من `package.json`.

> ملاحظة: النموذج **لن يحفظ** حتى تكمل الخطوة 2. ستظهر للزائر رسالة خطأ واضحة («لم يتم حفظ تسجيلك»)، ولن تظهر رسالة نجاح كاذبة ولن يُطلق `Lead`.

## 2) إعداد قاعدة البيانات (Neon Postgres عبر Vercel)

1. في مشروعك على Vercel: **Storage** (أو **Marketplace**) → **Neon** → Create → اربطها بالمشروع.
2. Vercel يضيف متغير `DATABASE_URL` تلقائيًا. إذا ظهر باسم مختلف، انسخ رابط الاتصال (يفضل **pooled**) وأضفه بالاسم `DATABASE_URL`.
3. افتح **Neon Console → SQL Editor**، والصق محتوى `db/schema.sql` وشغّله مرة واحدة.
4. أضف متغيرًا ثانيًا في **Settings → Environment Variables**:
   - `IP_HASH_SALT` = نص عشوائي طويل. لتوليده:
     `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
5. أعد النشر (**Redeploy**) حتى تُقرأ المتغيرات.

**عرض التسجيلات:** من SQL Editor:
```sql
SELECT created_at, first_name, email, whatsapp, consent_marketing,
       utm_source, utm_campaign, fbclid
FROM signups ORDER BY created_at DESC;
```
ولتصدير CSV استخدم زر التصدير في Neon.

**حذف شخص بناءً على طلبه:**
```sql
DELETE FROM signups WHERE lower(email) = lower('person@example.com');
```

## 3) إدخال Meta Pixel ID

1. من **Meta Events Manager** انسخ رقم الـPixel (أرقام فقط).
2. افتح `config.js` وضعه هنا:
   ```js
   META_PIXEL_ID: '123456789012345',
   ```
3. ارفع التعديل وأعد النشر.

- إذا تركته فارغًا، لا يُحمَّل أي Pixel ولا يظهر شريط الموافقة، والموقع يعمل بشكل طبيعي.
- `REQUIRE_COOKIE_CONSENT: true` (الافتراضي): لا يعمل Pixel إلا بعد ضغط الزائر «موافق». هذا يقلل عدد الأحداث المسجلة، لكنه الخيار الأحوط نظاميًا. لا تغيّره قبل مراجعة المتطلبات.

### الأحداث المركّبة

| الحدث | متى يُطلق | البيانات |
|---|---|---|
| `PageView` | كل صفحة (بعد الموافقة) | — |
| `ViewContent` | صفحة المنتج، مرة واحدة | `Muqabaltak` / `product` / `49` / `SAR` |
| `InitiateCheckout` | عند الضغط على أي زر شراء من الأزرار الثمانية، مرة واحدة لكل ضغطة | نفس بيانات المنتج |
| `Lead` | **فقط** بعد رد الخادم `201` بحفظ التسجيل فعليًا | `Muqabaltak` / `49` / `SAR` + `eventID = lead-<رقم التسجيل>` |
| `Purchase` | **لا يُطلق إطلاقًا** (محظور برمجيًا داخل `common.js`) | — |

لا يُرسل الاسم أو البريد أو الرقم إلى Meta. لم تُركّب Conversions API. الـ`eventID` جاهز لمنع التكرار إذا أضفتها لاحقًا.

## 4) خطوات اختبار التسجيل والأحداث بعد النشر

1. **Events Manager → Test Events** → أدخل رابط موقعك → Open Website.
2. افتح الصفحة الرئيسية بهذا الرابط:
   `/?utm_source=test&utm_campaign=qa&fbclid=TEST123`
   ثم اضغط **موافق** في شريط الموافقة. يجب أن يظهر `PageView` و`ViewContent`.
3. اضغط أي زر شراء. يجب أن يظهر `InitiateCheckout` مرة واحدة، وأن يحتوي رابط `checkout.html` على `utm_source=test`.
4. أرسل النموذج فارغًا. يجب أن تظهر رسائل خطأ بالعربي، وألا يظهر `Lead`.
5. سجّل ببريد جديد. يجب أن تظهر رسالة «تم تسجيل اهتمامك بنجاح!»، ثم `Lead` مرة واحدة. تحقق من ظهور الصف في Neon مع `utm_source = test`.
6. سجّل بنفس البريد مرة ثانية. يجب أن تظهر رسالة «بريدك مسجّل عندنا مسبقًا»، وألا يظهر `Lead` جديد.
7. تأكد أن `Purchase` لا يظهر في أي خطوة.
8. احذف صفوف الاختبار من قاعدة البيانات بعد الانتهاء.

## 5) الحماية المطبقة في `api/register.js`

- يتحقق الخادم من كل الحقول، ورسائل الخطأ بالعربي.
- يمنع تكرار البريد عن طريق فهرس فريد على `lower(email)`، فلا يتأثر بحالة الأحرف.
- مكافحة السبام:
  - حقل مخفي (Honeypot).
  - رفض الإرسال الأسرع من 2.5 ثانية.
  - حد أقصى 5 تسجيلات ناجحة في الساعة لكل IP.
  - حد أقصى 10 طلبات في الدقيقة لكل نسخة من الدالة.
- لا يُحفظ عنوان IP نفسه، بل بصمة HMAC منه.
- يُحفظ فقط:
  - الاسم الأول والبريد، والواتساب الاختياري بصيغة `+966…`.
  - الموافقتان ونسخة نص الموافقة.
  - مصدر الحملة (UTM و`fbclid`) وتاريخ التسجيل.
- لا توجد مفاتيح سرية في ملفات المتصفح.
